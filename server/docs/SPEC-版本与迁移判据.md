# 版本与迁移判据

> 目的：把「什么时候该抬 `DOCUMENT_FORMAT_VERSION` / `PROTOCOL_VERSION`」写成一条可执行的判据，
> 免得每加一个字段就反射式地抬双版本 + 写迁移 + 三端同批。
> 相关：`CODE-STRUCTURE.md` §0 / §3、`PLAN-降低改动面.md` 阶段 4。

---

## 0. 一句话

**抬版的唯一理由：旧读者会把新数据读错（画面 / 行为错，或丢数据、或卡住）。**
「字段变了」本身不是理由；「多了一个它不认识的字段」也不是。

## 1. 两个版本号，两条轨

| 版本号 | 住在哪 | 管什么 | 不一致的后果 |
|---|---|---|---|
| `DOCUMENT_FORMAT_VERSION` | `packages/document/src/types.ts` | 磁盘上的工程 / 场景文件 | 老编辑器读新文件：zod 丢掉不认识的键（**静默**），可能丢数据 |
| `PROTOCOL_VERSION` | `packages/protocol/src/messages.ts` | 编辑器 ↔ 服务端 ↔ 前端 的 wire | 握手不相等：服务端以 close `4002` 断开，三端必须同批 |

## 2. 判据：加东西前问三句

1. **老读者会崩吗？** —— 一般不崩（zod 丢键、未知组件走宽松分支）。崩也是「读不开」，不是「读错」。
2. **老读者会读错吗？**（画面错 / 行为错 / 丢数据 / 卡住）→ **会错就抬版**。
3. **只是多了一个它不认识的字段？** → **不抬**：新字段一律**可选 + 有默认值**，老读者丢掉 = 语义不变 / 用缺省。

### 2.1 不抬（新增式）

- 给已有组件 / 对象**加一个可选字段 + 默认值**（老读者丢掉 = 用缺省，画面不变）；
- **加一个新组件**（未知组件进宽松分支，老前端忽略它，其余照常镜像）；
- 给协议加一条**老前端会忽略的**消息（编辑器端自己用）。

### 2.2 要抬

- 字段的**含义 / 形状 / 枚举值**变了，或**默认值语义**变了（老读者按旧口径解释 = 读错）；
- 一次改动会让老前端**少渲染一层 / 播错东西**（「不是崩，是画面 / 行为错」）；
- **新增一条命令**：老服务端的入站 schema 会把不认识的命令判非法丢掉（编辑器那条 pending 永远收不到回执）——协议侧必须抬。

## 3. 各自的口径

### document（磁盘）

- 抬版 = 打开项目时**回写一次**，从此自描述；**没有迁移函数也能靠 schema 默认值**补。
- 因此历史做法是「格式有任何变化就 +1」。这是**安全的**，但不是必须的：
  按判据，纯新增可选字段可以不抬（老编辑器丢掉它、照常用）。
- **要抬**：需要跑迁移函数规范化老数据（字段搬家、改名、结构升级），或新字段会让老编辑器误改数据。

### protocol（wire）

- 抬版 = 握手 `4002`，编辑器与 Unity **必须同批更新**。成本比 document 高（跨语言）。
- 所以更严格遵守判据：**加法不抬**（可选字段 + 默认值就够），只有「会让老前端读错 / 不认识新命令」才抬。
- `PROTOCOL_VERSION` 的历史注释（`messages.ts` 顶部）本来就是按这条纪律写的，本判据只是把它讲成一句。

## 4. 与 C# 的关系

- 组件名 / 命令名常量已由 `pnpm gen:contract` 生成（阶段 0/1），**加名字不用手改 C#**；
- `Protocol.cs` 的 `Version = 26` 仍需**与 `PROTOCOL_VERSION` 同值**——抬版时必须一起改（并跑 Unity 编译）。

## 5. 现状

| | 值 | 说明 |
|---|---|---|
| `DOCUMENT_FORMAT_VERSION` | 35 | v35 将历史 kind 模板的初始必需组件显式落盘 |
| `PROTOCOL_VERSION` | 26 | v26 支持空图片渲染组件及 kind 无关的视图判定 |

> 本判据不追溯历史；从下一次改动起按它执行即可。
