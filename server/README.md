# DiceTaleStudio / server

跑团（TRPG）**Web 编辑器 + 服务端**。用于编辑地图网格、场景对象与对象上的动作，
并可在**运行状态**下连接前端（Unity 客户端）实时镜像状态、触发对象上的动作。

本仓库是 DiceTale 的下一代：`server/` 是编辑器与服务端，`client/`（Unity 前端）后续并入。

---

## 快速开始

```bash
cd server
pnpm install

pnpm dev            # 同时起后端（1420）与编辑器 Vite（5173）
# 或者分开：
pnpm dev:backend
pnpm dev:editor

pnpm --filter @dts/backend mock   # 另开一个终端：启动 Mock 前端
```

- 编辑器（开发）：<http://localhost:5173>（`/api` 与 `/editor`、`/client` 由 Vite 代理到后端）
- 编辑器（生产）：`pnpm build` 后由后端同源托管 <http://localhost:1420>
- 后端接口：`/api/projects`（列表 / 新建 / 删除）、`/api/projects/tree`、`/api/projects/folder`、
  `/api/health`、`/api/config`、`/api/resources/index`、`/api/resources/raw?id=...`、`/api/resources/text?id=...`、
  `/api/resources/rename`（重命名资源：`{from,to}` 逻辑 ID）、`/api/state`
- WebSocket：`/client`（前端）、`/editor`（编辑器）

| 命令 | 说明 |
|---|---|

| 批处理 | 说明 |

## 目录结构

```
server/
├─ apps/
│  ├─ editor/          # React 编辑器（四区布局、画布、属性面板、运行态 UI）
│  └─ backend/         # Node/TS：静态托管 + 资源 REST + 运行态 WS 中枢 + Mock 前端
├─ packages/           # 可独立测试的内部模块
│  ├─ grid/            # 网格位掩码、坐标转换、RLE、.bytes 编解码（零依赖）
│  ├─ document/        # 文档模型、zod 校验、组件注册表、补丁式撤销重做
│  ├─ actions/         # 动作注册表、条件求值、动作图校验
│  ├─ protocol/        # WS 消息契约（编辑器与后端共用同一份 zod schema）
│  ├─ resources/       # 资源逻辑 ID 规则、ResourceProvider 抽象、内存实现
│  └─ renderer/        # Canvas 2D 渲染器与视口变换（不依赖 React）
├─ resources/          # ★ 全部资源（见下）
├─ e2e/                # Playwright 用例
├─ test/               # 架构边界测试
└─ docs/specs/         # 设计文档
```

### 模块依赖规则（由测试强制）

```
editor  → document, actions, protocol, resources, renderer, grid
backend → protocol, resources
renderer→ grid
actions → document
document→ grid
protocol, resources, grid → （无）
```

约束写在 `test/architecture.test.ts` 里，破坏即测试失败：

1. `grid / document / actions / protocol / resources` **不得** import React、Node 内置模块或 DOM 全局；
2. `renderer` 可以用 DOM/Canvas，但**不得**依赖 React；
3. 包之间只允许上面声明的依赖方向，且必须写进各自 `package.json`；
4. 除 `resources` 包外，源码里**不得出现资源路径字面量**（一律用逻辑 ID）；
5. 只有后端 `FsResourceProvider` 能碰文件系统。

## 文档模型：项目 → 场景 → 对象

```
项目 project.json             ← 只有项目级数据（名称、道具库）
└─ 场景 Assets/scenes/<场景名>.json   ← 容器：所有对象都在场景上；**场景名就是文件名**
   ├─ 对象 SceneObjectDoc[]     ← 地图、门、宝箱、玩家、事件…都是普通对象
   │  ├─ 地图对象（kind=Map）    ← 携带贴图 + 网格数据
   │  └─ 其它对象                ← 携带若干能力组件与动作
   └─ （场景文件只有 objects；传送落点属于**运行态**，由前端上报，不在场景配置里）
```

**关键：对象挂在场景上，不挂在地图上**——所以没有地图也能在场景里放对象；
地图只是众多对象之一（可以有多个，也可以一个都没有）。

**场景是文件**（格式 v4 起）：一个场景 = `Assets/scenes/` 下的一个 `.json`，
**场景名不进文件内容**（它就是文件名）。因此重命名场景 = 重命名文件，内容一个字节都不用重写。
`project.json` 只剩项目级数据；旧版工程文件会在**打开项目时自动升级**（v1/v2 的内联场景拆成独立文件、
旧版场景文件按 v4 回写），只做一次。

**出生点（传送落点）已经不在代码里**：它既不属于场景配置，也不由前端上报。`Teleport` /
`TeleportZone` 动作的「目标标记点」参数仍然存在（那是发给前端的字符串，编辑器没有对应数据可校验）。

场景的建 / 删 / 改名在**顶部菜单「场景」**里（作用于当前场景），当前场景在**画布标题栏**上
看得见、也能直接切换：

| 位置 | 行为 |
|---|---|
| 画布标题栏的下拉框 | 显示当前场景名，选一下即切换 |
| 资源面板里的 `Assets/scenes/<场景名>.json` | 点一下即**打开**那个场景（当前场景那一行在目录里高亮） |
| 菜单「场景 → 新建场景…」 | 在 `Assets/scenes/` 下建一个空场景文件，并切到它 |
| 菜单「场景 → 重命名「当前场景」…」 | **只改文件名**（纯搬家，不重写内容） |
| 菜单「场景 → 删除「当前场景」」 | 删掉场景文件；至少保留一个场景 |

**没有「保存场景」的中间态焦虑**：新建 / 改名 / 删除场景是即时的文件操作，不碰场景内容；
场景**内容**（对象）的改动会自动存，也可以随时按「保存」/ `Ctrl+S` 立刻写。

编辑器左栏两个页签：

| 页签 | 作用 |
|---|---|
| 资源 | `Assets/` 的查看器（对齐 Unity Project 窗口：左目录树 + 右列选中目录的内容），**只读**；树根就是 `Assets`，项目名不出现在里面 |
| 场景对象 | 当前场景里的对象，**可改名 / 删除 / 复制**（创建走弹框，见下） |

### 新建对象：弹框

创建只有一条路，入口有三个（都指向同一个弹框）：

| 入口 | 说明 |
|---|---|
| 画布标题栏的「新建对象」 | 对象就长在场景上，入口也放在场景自己头上；**放在最右**，平板竖屏下左边可能被抽屉盖住 |
| `Ctrl/⌘+Shift+N` | 快捷键 |
| 菜单「编辑 → 新建对象…」 | 和复制 / 删除放在一起 |

弹框里**先分种类，种类下再选对象**：

| 种类 | 目前有的对象类型 |
|---|---|
| 实体 | **2D地图**（贴图与网格走默认值，贴图按同名约定指向 `Assets/images/<场景名>.png`） |
| 动作 | 先留空占位，后面慢慢加 |
| 事件 | 先留空占位，后面慢慢加 |

种类只是编辑器侧的归类，落进文档的仍然是对象的 `kind`（前端也认这个字段，不能为分类随意造新值）。
类型色点与画布上标记点的颜色同源；名字按类型自动预填且**自动避开重名**（`2D地图` → `2D地图 2`）；
没加对象类型的种类会明确写出「还没有对象类型」，创建按钮不可用。
点「创建」即生成在**场景正中**，之后在画布上拖到想要的位置。

### 场景对象的编辑与落盘

对象编辑是编辑器目前**唯一**会写场景内容的地方，落盘是「**自动存 + 手动保存**」：

- 改完 800ms 自动写回 `Assets/scenes/<场景名>.json`（连续拖动 / 连续输入只写一次）；
- 面板上的「保存」按钮与 `Ctrl/⌘+S` 立即写；底栏显示 未保存 / 保存中… / 已保存 / 保存失败；
- 待保存的场景**按内容差异算**，所以撤销、跨场景编辑都不会写错文件；切场景、关项目、
  新建 / 删除 / 重命名场景之前都会先 flush；
- 对象编辑全部走补丁式历史，**撤销 / 重做（`Ctrl+Z` / `Ctrl+Shift+Z`）可用**；场景级操作
  （增删改名）不入撤销栈。

画布上对象画成**按类型着色的标记点**：单击选中、**拖动即可定位**（落点换算与绘制共用同一个画布
区域尺寸）；位置为 `null`（只可能来自手写文件）的不画，列表里标「未放置」。
属性面板里能改名字与精确坐标（归一化 `0..1`，y 向下），`Ctrl/⌘+D` 复制选中、`Delete` 删除选中。

**列表不分组**：顶上是一排**种类按钮**（`全部` + 实体 / 动作 / 事件，与「新建对象」弹框同一套归类），
点一下就只看那个种类——还没做出对象的种类会写明「「动作」下还没有对象」，默认「全部」；
旁边还有关键字过滤框，两者叠加。"

**写回会规范化 JSON**：内容是 `JSON.stringify(..., 2)` 的结果，手写的缩进 / 注释 / 键顺序不保留。

新建出来的对象**组件与动作暂时是空的**（组件编辑尚未落地），所以对象目前只有名字、类型与位置。

没有项目 / 没有场景时，画布**不画假网格**（否则「什么都没有」看起来就像「有个空地图」），
而是和场景对象、属性面板一起给出空状态占位。**没有场景的占位本身就是入口**：
点一下直接弹「新建场景」，不用去菜单里找。画布在没有场景时也不接受平移缩放。

## 打开编辑器时

编辑器启动会跑一次**启动引导**（`bootstrapEditor`），规则只有三条：

| 情况 | 行为 |
|---|---|
| 有「上次打开的项目」且它还在 | **直接打开它**，不弹对话框 |
| 一个项目都没有 | 弹「**新建项目**」 |
| 有项目，但没有（或已失效的）上次记录 | 弹「**打开项目**」列表让用户挑 |

- 「上次打开的项目」记在**浏览器本地**（`localStorage`，见 `apps/editor/src/services/session.ts`）：
  打开动作由浏览器发起，服务端只知道文件夹在不在，不知道谁上次开了哪个项目。
- 主动「关闭项目」= **忘记**它，下次启动不会又把它拉回来。
- 记录失效（项目被删 / 改名 / 项目文件坏了）时自动清掉记录，退回「打开项目」列表，不会卡住。
- 引导是否跑完、弹了哪种对话框，通过外壳上的 `data-bootstrapped` 与 `data-project-dialog`
  暴露出来（e2e 据此等待引导结束，避免启动对话框把点击吃掉）。

## 资源：一个项目 = 一个文件夹 + 一个 project.json + 一个 Assets/

**每个项目是唯一的文件夹**，项目根只有两样东西：一个**固定名**的项目文件，和一个 `Assets/`
（模板参考 Unity：除项目文件外的一切都在 `Assets/` 下，项目根不随功能增长变乱）：

```
resources/
├─ config/                            编辑器全局配置（不属于任何项目）
│  ├─ app.json                        端口、资源目录名、项目标准子目录
│  ├─ editor.json                     编辑器默认值
│  └─ export.json                     导出目标
└─ projects/                          ★ 所有项目
   └─ 我的项目/                        ★ 一个项目一个唯一文件夹
      ├─ project.json                 ★ 项目文件（固定名；只有项目级数据）
      └─ Assets/                      ★ 所有资源都在这里
         ├─ config/                   该项目自己的配置
         ├─ scenes/                   ★ 场景：<场景名>.json（场景名就是文件名）
         ├─ images/                   图片资源：场景贴图 <场景>.png（与场景同名）
         ├─ audio/
         └─ video/
```

编辑器里：「工程 → 新建项目」起个名字即创建出上述结构；「工程 → 打开项目」列出所有项目。
场景（含网格与对象）是 `Assets/scenes/<场景名>.json` 独立文件；`Assets/` 下还放导出物与素材。

**资源不由编辑器写入**：素材由人 / 外部工具**提交到这些指定目录**，编辑器只负责查看与引用，
所以资源面板目前是**只读**的（没有新建 / 导入 / 删除入口）。例外只有两类，都不碰素材本身：
场景的三个文件级操作（新建 / 重命名 / 删除），以及**场景对象的编辑**（写的是 `Assets/scenes/`
下的场景文件，不是 `Assets/` 里的素材）。

**选中资源看属性**：在资源面板里点一个文件即选中它，属性面板显示名称 / 路径 / 类型 / 大小，
图片还会读出**真实像素尺寸**；图片、视频、音频直接在属性面板里预览。预览走后端的原始字节接口
（`/api/resources/raw?id=...`），所以刚提交进目录的素材刷新一下就能看到，不需要先「导入」。
列表里**不显示扩展名**（`Map001.png` 显示为 `Map001`），完整文件名在属性面板里看。
例外：`Assets/scenes/` 下的场景文件点一下是**打开那个场景**（不是看属性），
当前场景那一行会在目录里高亮——对齐 Unity「Project 窗口里双击场景即打开」的习惯。

**属性面板不跟场景绑定**：选中资源看资源属性、选中对象看对象属性，都没选时看**项目属性**
（名称 / 文件夹 / 场景数 / 资源文件数）——打开着项目就总有内容，不会因为「没有场景」而空白。

**判定标准只有一条：文件夹里有 `project.json` 才是项目。** 没有的目录（半途创建、只剩资源的残骸）
不会出现在「打开项目」列表里，也不算存在——`listProjects` 直接过滤掉它们。

`Assets/` 下的标准目录是 `config`、`scenes`、`images`、`audio`、`video` 五个。
**没有 `maps/`**（地图只是场景里的一个对象，数据按场景放 `Assets/scenes/`），
**也没有 `items/`**（道具库存在项目文件里）。

仓库里带一个 `测试项目/` 作为样例（也是手测用的空项目）；E2E 不会碰它——
Playwright 跑在临时资源根上（见 `playwright.config.ts` 的 `DTS_RESOURCES_DIR`）。

- 资源用**逻辑 ID** 寻址，只有两个类别：`config:`（编辑器全局）与 `project:`（项目内容）。
  例如 `project:我的项目/project.json`、`project:我的项目/Assets/images/Map001.png`。
- **特殊文件不出现在资源面板里**：`project.json` 是项目元数据、不是项目内容，
  资源树会跳过它（`PROJECT_SPECIAL_FILES`）——因此它既不显示，也无法从面板里被删掉
  （删掉它项目就不成立了）。只挡项目根的那一个，子目录里同名的文件照常显示。
- 项目文件夹名、标准子目录名与项目文件名集中在 `packages/resources/src/ids.ts`
  （`PROJECT_FOLDERS`、`PROJECT_FILE_NAME`）；资源根与 `projects` 目录名由 `config/app.json` 的 `dirs` 声明。
- 逻辑 ID → 真实路径的解析只发生在 `ResourceProvider` 实现里（后端 `FsResourceProvider`、编辑器 `HTTP`、测试 `Memory`）。
- 项目名会直接成为文件夹名，因此会挡掉路径分隔符、Windows 非法字符与 `CON`/`NUL` 等保留名。
- 大体积二进制（地图贴图、音视频）默认不入库，需要时 `git add -f` 或启用 Git LFS。

## 编辑态 / 运行态

- **编辑态**：编辑场景对象（新建 / 改名 / 删除 / 复制 / 拖动定位），全程可撤销/重做（补丁式历史，
  连续拖拽 / 复制会合并成一条记录）；地图网格、组件与动作的编辑尚未落地。
- **运行态**：连接服务端，实时镜像前端状态（当前地图、玩家、对象、可触发动作），并可一键触发动作。

**运行态数据与编辑文档物理隔离**：镜像放在独立的 `runtime` 状态里，永不写回文档，也不进撤销栈。

## 告诉前端执行一个动作：三级降级

| 场景 | 下发 | 前端行为 | 依赖 |
|---|---|---|---|
| 触发前端已配置好的动作（**主路径**） | `invoke_action{objectId, actionId}` | 按 id 找动作 → 评估条件 → 执行效果 | 需前端实现下方契约 |
| 动作只在编辑器里编排（v2 服务端权威） | 服务端求值后下发原子命令序列 | 执行 `set_option` 等，本地动作链产生副作用 | 待实现 |
| 只想改某个值 | `set_option` / `set_bool` / `set_int` / `set_float` … | 组件改值 → 本地动作链 | **现在就能用** |

前端（Unity）当前未开放，因此运行态用 **Mock 前端**（`apps/backend/src/mock-client`）先行验证：
它实现同一套 `/client` 协议，上报对象与动作清单，并对 `invoke_action` 回执。
端到端链路已有测试锁定（`apps/backend/test/runtime-hub.test.ts`）。

## 前端（Unity 客户端）需要配合的最小契约

待前端开放后实施，详见 `docs/specs/`：

1. `BackendChangeAction` 增加可序列化稳定 `actionId`（跨会话稳定，用于远程寻址动作）。
2. 注册上报增加动作清单：`{ type: "register_actions", objectId, componentId, actions: [{ actionId, type, displayName, paramSummary, conditionSummary }] }`。
3. `ServerCommandDispatcher` 增加 `invoke_action` 分支：定位对象 → 按 `actionId` 找动作 → 执行 → 回 `action_result`。
   注意动作挂在组件上，需要一条**按动作 id 定位的旁路**，不改动现有「按命令类型路由组件」的语义。
4. 条件求值保持现状（客户端本地 `Satisfies`）；服务端权威求值作为后续可选项。

协议定义以 `packages/protocol` 为唯一来源（编辑器与后端共用，入站消息全部经过 zod 校验）。

## 坐标契约（务必遵守）

三套坐标系并存，历史上这里反复出错：

| 坐标系 | 方向 |
|---|---|
| 图像像素 | 原点左上，x 向右，**y 向下** |
| 归一化（协议/GM 面板） | `[0,1]`，**y 向下** |
| 网格（与 Unity `GridMap` 一致） | x 向右，**y 向上**；`y = 0` 是图片**最下面**一行 |

换算恒等式：`gridY = height - 1 - imageRow`。
所有换算必须走 `packages/grid/src/coords.ts`，**不要在别处再写一遍**。
`.bytes` 的行序固定为 `bottom-up`（文档里显式声明 `rowOrder`），`Map001` 实测：1920×1080 图 / 64×36 格 / 每格 30px。
