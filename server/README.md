# DiceTaleStudio / server

跑团（TRPG）**Web 编辑器 + 服务端**。用于编辑地图网格、场景对象与对象上的动作，
并可在**运行状态**下把当前场景推给前端（Unity 客户端）——**后台有什么对象，前端就有什么对象**，
前端只做镜像与播放；命令（如播放声音）由后台下发。

本仓库：`server/` 是编辑器与服务端，`client/` 是 Unity 前端（见 `client/README.md`）。

---

## 快速开始

```bash
cd server
pnpm install

pnpm dev            # 同时起后端（1420）与编辑器 Vite（5173）
# 或者分开：
pnpm dev:backend
pnpm dev:editor

pnpm --filter @dts/backend mock   # 另开一个终端：启动 Mock 前端（先让编辑器点「运行」它才连得上）
```

- 编辑器（开发）：<http://localhost:5173>（`/api` 与 `/editor`、`/client` 由 Vite 代理到后端）
- 编辑器（生产）：`pnpm build` 后由后端同源托管 <http://localhost:1420>
  （产物文件名带内容哈希，所以**重新构建之后手头开着的页面要刷新一次**；后端对缺失的产物文件
  返回 404 而不是把 `index.html` 塞回去——否则浏览器会拿 HTML 当 JS 模块解析，页面直接白屏卡死）
- 后端接口：`/api/projects`（列表 / 新建 / 删除）、`/api/projects/tree`、`/api/projects/folder`、
  `/api/projects/reveal`（在服务端那台机器上用文件管理器打开项目目录）、
  `/api/health`、`/api/config`、`/api/resources/index`、`/api/resources/raw?id=...`、`/api/resources/text?id=...`、
  `/api/resources/rename`（重命名资源：`{from,to}` 逻辑 ID）、
  `/api/state`（运行态摘要：开没开闸 / 前端是谁 / 镜像的是哪份场景）
- WebSocket：`/client`（前端，**只有编辑器点了「运行」才接受连接**）、`/editor`（编辑器）

## 常用脚本（在 `server/` 下执行）

| 命令 | 说明 |
|---|---|
| `pnpm dev` | 后端 + 编辑器开发服务器 |
| `pnpm build` | 构建编辑器产物到 `apps/editor/dist`（E2E 前必须先跑） |
| `pnpm typecheck` | 全部包类型检查 |
| `pnpm test` | 单元测试 + 架构边界测试（约 1.5s） |
| `pnpm check` | 类型检查 + 单测 + Lint（提交前一把过） |
| `pnpm lint` | ESLint |
| `pnpm e2e:fast` | Playwright **只跑桌面档位**（约 10s）：改完先拿它验，别一上来就跑全量 |
| `pnpm e2e` | Playwright 全量（桌面 + 两个平板档位，约 40s）；跑在**临时资源根**上，不碰仓库 `resources/` |

E2E 是**完全并行**的（`fullyParallel`，worker 数默认按核数一半、封顶 8；`E2E_WORKERS=1` 可
回到串行复现时序问题）。这要求用例**自建自删项目**、各用各的 page——写新用例时别破坏这两条，
否则会变成「偶发失败」，那比跑得慢更难受。跑 E2E 前记得 `pnpm build`：它托管的是**已构建**产物。

唯一的例外是带 **`@runtime`** 标记的那组用例（编辑态 / 运行态，见 `e2e/smoke.spec.ts`）：
它们开关的是**服务端全局单例**，开着的时候别的用例一打开编辑器也会跟着进运行态（落盘断言会超时），
关闸时那一边还会被还原。所以这两个脚本都是**两趟**：先并行跑其余用例（`--grep-invert @runtime`），
再把这组单独、串行跑（`--grep @runtime --workers=1`）。手工敲 `npx playwright test` 时请照抄这个分法。

Windows 下也可以直接双击批处理（`server/` 目录内，GBK + CRLF，中文提示）：

| 批处理 | 说明 |
|---|---|
| `command-install.bat` | 检查 node/pnpm 后安装依赖；失败时提示设置代理 |
| `command-build.bat` | 全包类型检查 + 构建编辑器产物 |
| `command-start.bat` | 单端口启动服务端并托管编辑器；默认不弹浏览器（`--open` 可开）；默认监听 `0.0.0.0` 供同一 WiFi 的手机/平板访问；带端口占用预检 |
| `command-open-port.bat` | 放行 Windows 防火墙入站端口（自动 UAC 提权；`--print` 只看命令不改系统） |

## 目录结构

```
server/
├─ apps/
│  ├─ editor/          # React 编辑器（四区布局、画布、属性面板、运行态 UI）
│  └─ backend/         # Node/TS：静态托管 + 资源 REST + 运行态 WS 中枢 + Mock 前端
├─ packages/           # 可独立测试的内部模块
│  ├─ grid/            # 网格位掩码、坐标转换、RLE、.bytes 编解码（零依赖）
│  ├─ document/        # 文档模型、zod 校验、组件注册表、补丁式撤销重做
│  ├─ actions/         # 动作注册表、条件求值、动作图校验
│  ├─ protocol/        # WS 消息契约（编辑器与后端共用同一份 zod schema）
│  ├─ resources/       # 资源逻辑 ID 规则、ResourceProvider 抽象、内存实现
│  └─ renderer/        # Canvas 2D 渲染器与视口变换（不依赖 React）
├─ resources/          # ★ 全部资源（见下）
├─ e2e/                # Playwright 用例
├─ test/               # 架构边界测试
└─ docs/specs/         # 设计文档
```

### 模块依赖规则（由测试强制）

```
editor  → document, actions, protocol, resources, renderer, grid
backend → protocol, resources
renderer→ grid
actions → document
document→ grid
protocol, resources, grid → （无）
```

约束写在 `test/architecture.test.ts` 里，破坏即测试失败：

1. `grid / document / actions / protocol / resources` **不得** import React、Node 内置模块或 DOM 全局；
2. `renderer` 可以用 DOM/Canvas，但**不得**依赖 React；
3. 包之间只允许上面声明的依赖方向，且必须写进各自 `package.json`；
4. 除 `resources` 包外，源码里**不得出现资源路径字面量**（一律用逻辑 ID）；
5. 只有后端 `FsResourceProvider` 能碰文件系统。

## 文档模型：项目 → 场景 → 对象

```
项目 project.json             ← 只有项目级数据（名称、道具库）
└─ 场景 Assets/scenes/<场景名>.json   ← 容器：所有对象都在场景上；**场景名就是文件名**
   ├─ 对象 SceneObjectDoc[]     ← 地图、门、宝箱、玩家、事件…都是普通对象
   │  ├─ 地图对象（kind=Map）    ← 携带贴图（map.image）+ 网格数据
   │  ├─ 精灵 / 玩家 / 道具…     ← 可携带一张**图片**（image），显示在世界里
   │  └─ 其它对象                ← 携带若干能力组件与动作
   └─ （场景文件只有 objects；传送落点属于**运行态**，由前端上报，不在场景配置里）
```

**关键：对象挂在场景上，不挂在地图上**——所以没有地图也能在场景里放对象；
地图只是众多对象之一（可以有多个，也可以一个都没有）。

**场景是文件**（格式 v4 起）：一个场景 = `Assets/scenes/` 下的一个 `.json`，
**场景名不进文件内容**（它就是文件名）。因此重命名场景 = 重命名文件，内容一个字节都不用重写。
`project.json` 只剩项目级数据；旧版工程文件会在**打开项目时自动升级**（v1/v2 的内联场景拆成独立文件、
旧版场景文件按当前版本回写——位置在 v5 换算成世界坐标、网格里的 `cellSize` 在 v6 删掉、
每个对象补上 `active` / `sortingOrder` 在 v7、补上 `scale` 在 v8、补上 `locked` 在 v9；
地图的 `map.fog`（战争雾）是 v10 起的**可选**字段，**不补空壳**；单轴缩放 `scaleX` / `scaleY`
是 v11 起的**可选**字段，同样**不补空壳**），只做一次。

**出生点（传送落点）已经不在代码里**：它既不属于场景配置，也不由前端上报。`Teleport` /
`TeleportZone` 动作的「目标标记点」参数仍然存在（那是发给前端的字符串，编辑器没有对应数据可校验）。

场景的建 / 删 / 改名在**顶部菜单「场景」**里（作用于当前场景），切换则在**画布上方的场景
切换条**上——**一格一张图、点一下即切**，当前那格高亮：

| 位置 | 行为 |
|---|---|
| 场景切换条（画布标题栏下面） | 一格一个场景，点一下即切；当前那格高亮；放不下时横向滚动，当前格自动滚进可视区 |
| 切换条两端 `‹` / `›` | 上一场 / 下一场（到首 / 尾就停住，**不循环**） |
| 键盘 `1`–`9` | 直选切换条上的第 N 格（序号画在前九格上）；`[` / `]` = 上一场 / 下一场。在输入框里打字时不响应 |
| 菜单「场景 → 上一场 / 下一场」 | 和切换条同一套动作（平板没有键盘，所以菜单里也各有一份） |
| 资源面板里的 `Assets/scenes/<场景名>.json` | 点一下即**打开**那个场景（当前场景那一行在目录里高亮） |
| 菜单「场景 → 新建场景…」 | 在 `Assets/scenes/` 下建一个空场景文件，并切到它 |
| 菜单「场景 → 重命名「当前场景」…」 | **只改文件名**（纯搬家，不重写内容） |
| 菜单「场景 → 删除「当前场景」」 | 删掉场景文件；至少保留一个场景 |

**换台的两条手感约定**（跑团时一次点击就到位）：

- **运行态下切场景会立刻推给前端**（不等 200ms 去抖）——投影 / 电视上换的就是 DM 刚切的那张图，
  不用再去运行面板点「重新同步」；
- **视口跟着场景走**：切到**没去过的**场景自动适配（把那张图上看得见的东西一起装进画布），
  切回**去过的**场景回到上次的缩放与平移（本次会话内记住，不落盘）。

**顺序**按场景名排（中文拼音序 + 数字按数值比）：`第2幕` 排在 `第10幕` 前面、`02-大厅` 排在
`10-地窖` 前面。所以想固定「跑团顺序」，用编号命名（`01-门厅`、`第2幕-地牢`）就够——
序号就是快捷键的说明书。

**没有「保存场景」的中间态焦虑**：新建 / 改名 / 删除场景是即时的文件操作，不碰场景内容；
场景**内容**（对象）的改动会自动存，也可以随时按「保存」/ `Ctrl+S` 立刻写。

编辑器左栏两个页签（**场景对象在前，默认停在它上面**）：

| 页签 | 作用 |
|---|---|
| 场景对象 | 当前场景里的对象，**可改名 / 显示隐藏（行首那只眼睛）/ 删除 / 复制**（创建走弹框，见下） |
| 资源 | `Assets/` 的查看器（对齐 Unity Project 窗口：左目录树 + 右列选中目录的内容），**只读**；树根就是 `Assets`，项目名不出现在里面 |

### 新建对象：弹框

创建只有一条路，入口有三个（都指向同一个弹框）：

| 入口 | 说明 |
|---|---|
| 画布标题栏的「新建对象」 | 对象就长在场景上，入口也放在场景自己头上；**放在最右**，平板竖屏下左边可能被抽屉盖住 |
| `Ctrl/⌘+Shift+N` | 快捷键 |
| 菜单「编辑 → 新建对象…」 | 和复制 / 删除放在一起 |

弹框里**先分种类，种类下再选对象**：

| 种类 | 目前有的对象类型 |
|---|---|
| 实体 | **网格地图**（贴图与网格走默认值，贴图按同名约定指向 `Assets/images/<场景名>.png`）、**精灵** |
| 动作 | **播放声音**（只带「音频列表 + 选中的那条 + 层级」，是一句**告诉前端播什么**的指令）、**传送阵**（只带「候选场景 + 选中的那一张」，**按一下 = 切换当前场景**） |
| 事件 | 先留空占位，后面慢慢加 |

种类只是编辑器侧的归类，落进文档的仍然是对象的 `kind`（前端也认这个字段，不能为分类随意造新值）。
**「网格地图」= `kind: "Map"`，「精灵」= `kind: "SceneObject"`**：精灵复用了既有的场景对象 kind
（前端无需配合认新值），两者只是显示名不同；改名 / 删除 / 复制 / 拖动对两者一视同仁
（地图也是世界里的对象，拖它就是移动贴图）。**「播放声音」= `kind: "PlaySound"`** 与
**「传送阵」= `kind: "Teleport"`** 是编辑器侧新增的类型：两者都是**动作对象**，前端**不建可见物**
（一个 GameObject 都不建，数据留在镜像里够用——见下「动作对象」两节与前端契约）。
**精灵就是「显示图片的对象」**：属性面板里给它挑一张图（「选择」按钮 → 选择图片弹框），
它就画在自己那块矩形上——矩形 = 位置（中心）+ 引用里声明的图片尺寸，和地图贴图**同一套规矩**；
没挑图片的精灵只画一个标记点。
类型色点与画布上标记点的颜色同源；名字按类型自动预填且**自动避开重名**（`网格地图` → `网格地图 2`）；
没加对象类型的种类会明确写出「还没有对象类型」，创建按钮不可用。
点「创建」即生成在**世界原点**（画布正中），之后在画布上拖到想要的位置——**声音对象也一样**
（它在画布上是一枚音频徽标，见下一节）。

### 场景对象的编辑与落盘

对象编辑是编辑器目前**唯一**会写场景内容的地方，落盘是「**自动存 + 手动保存**」：

- 改完 800ms 自动写回 `Assets/scenes/<场景名>.json`（连续拖动 / 连续输入只写一次）；
- 面板上的「保存」按钮与 `Ctrl/⌘+S` 立即写；底栏显示 未保存 / 保存中… / 已保存 / 保存失败；
- 待保存的场景**按内容差异算**，所以撤销、跨场景编辑都不会写错文件；切场景、关项目、
  新建 / 删除 / 重命名场景之前都会先 flush；
- 对象编辑全部走补丁式历史，**撤销 / 重做（`Ctrl+Z` / `Ctrl+Shift+Z`）可用**；场景级操作
  （增删改名）不入撤销栈。

**画布上的对象就是它那块矩形**（不再有「中心标记点」）：**鼠标左键**点矩形内任意一处即**选中**它
（对象不会被跟手拖走，想摆位置用移动工具的手柄）；拾取、选中框、贴图铺的位置**共用同一块矩形**，
所以「看到的框」与「点得到的范围」永远一致。
重叠时点到的永远是**显示顺序最大**的那一个（和眼睛看到的一致）；按住 `Ctrl/⌘/Shift` 点可多选。
**只有主键（左键 / 触摸 / 笔尖）拾取与拖动**，中键、右键一律不参与（右键留给将来的上下文菜单）。
选中时矩形上画**4 个角点 + 4 条边中点**（没有中心点）；点空白处取消选中，
而从空白处**拖动**始终是平移画布（不会顺手把选中丢掉）。没有图片的对象用 64×64 的矩形兜底。
拾取在**世界坐标**里判定，因此与缩放无关——放大 8 倍点，命中的还是同一个对象。
属性面板里能改名字与精确坐标（**世界坐标，单位像素**，y 向上），`Ctrl/⌘+D` 复制选中、`Delete` 删除选中。
**没落点的对象**（`position: null`，只可能来自手写文件或旧版数据）在画布上**不画、也点不到**，
看起来就像「这个对象没了」——所以那种对象的「世界坐标」那一行多一个「**落位**」按钮：
点一下放到世界原点，之后照常拖、照常缩放。画布中心画了一个**原点十字**，一眼能看出 0,0 在哪。

#### 变换手柄：拖动 / 移动 / 旋转 / 缩放（对齐 Unity 的 Scene 视图）

**画布左上角**有一个四段开关（`拖动` / `移动` / `旋转` / `缩放`，快捷键 `Q` / `W` / `E` / `R`，
「视图」菜单里也各有一份——平板没有键盘，所有命令都得能从菜单触发）。
它改的是「**在画布上拖动会发生什么**」，所以贴在画布上而不是塞进标题栏：

- **默认是「拖动」，它只动摄像机**：拖哪儿都是平移画布；**拖对象只是选中它**，不会把它碰歪。
  这个状态下**不显示任何手柄**；
- **对象一律不跟手拖走**（任何工具下都一样）：想摆位置就用「移动」工具的 X / Y 箭头。
  于是「顺手把对象碰歪」这件事根本不会发生；按住对象拖动 = 平移画布，手势仍然有用；
- 选中对象后，画布上**只画当前工具的那一套手柄**（对齐 Unity：切工具就是换手柄的样子）。
  为此，**有工具在用时选中框只留虚线框、不再画那 8 个装饰方块**——它们和缩放手柄是同一种方块、
  同尺寸同配色，一起画出来会被读成「移动模式下也出现了缩放的 UI」。
  选中框的装饰方块只在「拖动」工具下出现（那时没有任何手柄，它们就是唯一的手柄提示）；
- 三套手柄都是屏幕像素尺寸，而且**都贴着对象的外框往外量**：对象多大，手柄就长在多大的框外面
  （不会出现小对象的手柄离它老远、大对象的手柄压在它身上）。缩到 0.05 倍或放到 16 倍都看得见、点得到：
  - **移动**：外框外两根轴条 + 箭头，拖 X 箭头**只沿 X 走**、拖 Y 箭头只沿 Y 走；
  - **旋转**：围绕整个对象的一圈细环（半径 = 外框对角线 + 一段间距，所以永远在对象外面），
    沿环拖动 = 绕对象中心旋转，按住 `Shift` 吸附到 **15°** 的整数倍；
  - **缩放**：外框八个方位的方块——拖**角**等比、拖**边**只改那一个轴；按住 `Shift` 强制等比。
- 手柄的**命中与绘制共用同一份屏幕几何**（`@dts/renderer` 的 `gizmoScreenGeometry`），
  所以不存在「看得见的柄点不中」；
- 手柄跟着对象的**角度**一起转（对象转过 90°，它的缩放柄也转过去了，改的仍是对象自己的 X / Y 轴）；
- **锁定的对象手柄画成灰色且点不到**（不是不画——要能一眼看出「为什么拖不动」）；
- 一次手柄拖拽是**一条撤销记录**（拖动中连续写文档会按 `transform:<id>` 合并，
  抬手断开；`Esc` 可放弃这次拖拽并回到按下前的样子）；
- 对象在屏幕上太小时（矩形不足 14px）**只画框、不画手柄**：7px 的柄会比对象本身还大。
- **多选不出手柄**：手柄只作用于单选（Unity 会把整体缩放，这里暂不支持）。
  多选时每个对象仍画自己的选中框。

> 画布上的浮层控件（工具开关）**不会**被画布的手势接管：容器的 `pointerdown` 只处理
> 落在 `<canvas>` 上的按压。少了这条判断，`setPointerCapture` 会把指针从按钮上抢走，
> `pointerup` / `click` 都不再发给按钮——表现是「按钮点了没反应」。

**地图是世界里的对象，不是「场景背景」**（对齐 Unity）：每张地图有**自己的世界坐标**
（= 贴图中心）与自己的贴图尺寸——它占世界里的哪块矩形、它的格子从哪儿数，全由它自己决定；
改坐标 / 拖它，**贴图跟着走**。一张场景里可以有**任意多张**地图，各画各的（贴图、格子、
网格线都裁剪在各自那块矩形里，互不干扰）。

**图片会画在场景里**：对象要显示的图片（地图的 `map.image`、精灵的 `image`）由编辑器经
`/api/resources/raw` 拉取后铺满**它自己那块矩形**（世界坐标 = 位置 + 声明尺寸），
网格线叠在它上面。绘制顺序是 **`sortingOrder` 小的先画**（大的盖在上面），
相同的保持场景文件里的先后；新建时地图默认 `-10`、其它对象 `0`，所以「地图垫底、精灵在上」开箱即对。

- **每个对象都有激活开关**（对齐 Unity）：列表里每行一枚眼睛按钮，属性面板里是「激活」勾选框。
  不激活的对象**完全不画**，也不参与画布上的点选与拖动——但它**仍在场景里**（列表还在、属性照改），
  和「删除」是两回事。
- **`sortingOrder` 决定谁挡住谁**（与坐标无关）：属性面板里可改，连续输入合并成一条撤销记录；
  大的画在前面，相同则按场景对象列表里的先后。
- **锁定**（列表里那把锁 / 属性面板的「锁定」勾选框）：锁上的对象**不能被移动**——在画布上拖它
  不会动（拖它等于平移画布），世界坐标输入框也禁用。别的照常可改（改名 / 显示顺序 / 缩放 / 激活 /
  换贴图 / 地图的网格标注），也不影响**选中**与**删除**；锁住的选中框在画布上画成**灰色**，
  一眼看出「为什么拖不动」。

- 地图占多大由**地图数据里声明的贴图尺寸 × 该轴的有效缩放**决定（网格就是按它排的：缩放地图 =
  贴图与网格格子一起缩放），精灵就是**图片自己的像素尺寸 × 有效缩放**（1 图片像素 = 1 世界像素，
  再乘缩放）；`naturalWidth` 只用来核对「贴图真实像素 vs 声明像素」，两者不一致时按声明尺寸拉伸，
  并在控制台提醒一次（与缩放无关）。**每个对象都有等比 `scale`，默认 1**，属性面板的「基础」里可改。
- **缩放支持单轴**（v11 起，见「旧文件的迁移」）：属性面板「缩放」那一行有个**等比锁**，
  打开时只有一个「缩放」框（改它两轴一起动），关掉后露出 `缩放 X` / `缩放 Y` 各自独立。
  两轴被改成相等时**自动折叠**回等比 `scale`——文件里「等比」只有一种写法。
- 图片按逻辑 ID 缓存（来回切场景不重复下载），**切项目 / 关项目时释放**。
- 画布**底色是黑灰棋盘底纹**，铺满整个视口且锚在世界坐标上（无地图时锚世界原点，有地图时锚
  **第一张地图矩形的左下角**）——所以平移 / 缩放时底纹跟着走，格子还和地图的网格对齐。
  底纹**只画这一层**：贴图（包括地图贴图）的透明处、还没加载好的地方、地图之外的空白，
  透出来的都是它，不会突然出现一块「比别处更黑的方块」。
- **读不到图片就说清楚原因**（画布左上角一条「地图贴图未显示：找不到资源 `<逻辑 ID>`」，
  多张都读不到时依次列出），不会静默只留一块底纹。
  **地图贴图必须与场景同名**（`Assets/scenes/场景1.json` ↔ `Assets/images/场景1.png`）：
  对不上时贴图就是找不到，提示里的逻辑 ID 直接指出它在找哪个文件。
- **重命名场景会同步这个引用**：若**地图**的贴图正指向旧场景名（即「与场景同名」的那张），
  改名时一起改指到新名字——否则场景一改名，贴图立刻就找不到了。**精灵的图片不动**：
  那是用户明确挑的文件，哪怕它和场景同名，改指到别的文件反而是篡改。
- 属性面板**「渲染」组**里的图片**只显示项目内相对路径**（`images/Map001.png`，省掉 `project:`、项目名与 `Assets/`），
  后面跟一个「**选择**」按钮：打开「选择图片」弹框，从**项目里已有的图片**里挑一张
  （对齐 Unity 的 Object Picker；编辑器不导入素材，所以只挑不加）。换图时宽高从素材本身读出；
  地图**网格尺寸不变**——网格是导入时按贴图算好的，换图不该悄悄改动格子数。
  引用的文件不在项目里时，路径旁会标一个「找不到」，点「选择」即可换一张；
  没有图片的对象显示「（无贴图）」和同一个「选择」入口。
- 属性面板里**列数 / 行数可以直接改**（改尺寸就按新规格重建格子数据）；**每格**那行是只读的，
  因为它**算出来的**（`贴图宽 ÷ 列数`）——1920×1080 分 64×36 格就显示 `30 × 30 px`，
  列数改成 32 就变成 `60 × 30 px`。

**列表不分组**：顶上是一排**种类按钮**（`全部` + 实体 / 动作 / 事件，与「新建对象」弹框同一套归类），
点一下就只看那个种类——还没做出对象的种类会写明「「动作」下还没有对象」，默认「全部」；
旁边还有关键字过滤框，两者叠加。"

**写回会规范化 JSON**：内容是 `JSON.stringify(..., 2)` 的结果，手写的缩进 / 注释 / 键顺序不保留。

新建出来的对象**组件与动作暂时是空的**（组件编辑尚未落地），所以对象目前只有名字、类型与位置
（动作对象多一份「音频列表 + 选中的那条 + 层级」，见下节）。

没有项目 / 没有场景时，画布**不画假网格**（否则「什么都没有」看起来就像「有个空地图」），
而是和场景对象、属性面板一起给出空状态占位。**没有场景的占位本身就是入口**：
点一下直接弹「新建场景」，不用去菜单里找。画布在没有场景时也不接受平移缩放。

### 动作对象：播放声音

**「动作」种类下的第一个对象**。它**和实体一样摆在世界里**：「基础」那组属性（名称 / 类型 /
激活 / 锁定 / 显示顺序 / 世界坐标 / 缩放）一个不少，画布上能点选、能拖、能被别的对象挡住；
在此之上多一组「声音」，携带**加进来的音频列表 + 选中的那条**与**层级**，声明
「**要告诉前端播什么**」。

编辑器**不播放**：面板里没有试听、不碰音频解码，这份清单原样写进场景文件，出声是前端的事。

| 参数 | 说明 |
|---|---|
| **层级** | 固定四档：**背景音乐 / 环境音 / 音效 / 语音**（**排在音频上面**）。它是**声道分组**：同层同时只响一条，播新的时旧的停；要两件事同时响就分到两层 |
| **音频** | 面板把**加进来的音频全列出来**（一排小方块，**单选**）：点一下就把「播哪一条」切过去，选中的那条就是前端会播的。加 / 删音频与起名字在下面那行「**编辑音频…**」的窗口里（见下）。一条都没加 = 这条声音还不响 |

**画布上的样子是固定的**：给它画一枚**内置的音频图标**——**实色**圆角牌（类型色）+
**深色外描边** + 白色喇叭与声波，按那块矩形等比缩放；全部用路径画，不占资产也不依赖字体。
实色 + 外描边是为了**在花花绿绿的贴图上也抠得出来**（早先那版用半透明粉底，压在草地 / 水面
上几乎看不见）。所以刚建出来的声音对象**看得见、点得到、拖得动**，不会变成场景里一个找不到的
隐形对象。**图标不允许改**：属性面板里没有「渲染」这一组、也没有换贴图的入口；手写文件里若挂了
`image` 字段，`validateScene` 会给一条警告（编辑器不认它）。列表行尾显示的是它落在**哪一层**。

**正在播时这枚图标是活的**：外面**一圈圈往外扩的声波**（1200ms 一圈、两圈错开半个周期，边走边淡）
+ 牌面里的喇叭一胀一缩（参数是纯函数 `audioBadgeAnimation`，在 `packages/renderer`）。
编辑器自己不出声，画布上「有个音频正在响」就只能靠**看得见的变化**表达——静态图标谁也分不出它
是在响还是待命。记账一变下一帧就变（画布本来就每帧重绘，不用另起定时器），所以点「播放 / 停止」
时不用另做什么，图标自己就动起来 / 停下来。

落盘在场景文件里（位置与其它对象同一个口径）：

```json
{ "kind": "PlaySound", "position": { "x": 0, "y": 0 }, "scale": 1,
  "sound": { "clips": ["project:项目/Assets/audio/step1.mp3",
                       "project:项目/Assets/audio/step2.mp3"],
             "picked": "project:项目/Assets/audio/step2.mp3",
             "names": { "project:项目/Assets/audio/step1.mp3": "雷雨" }, "layer": "sfx" } }
```

`clips` 是**加进来的**音频（顺序 = 加进来的先后，没有别的语义）；`picked` 是**当前选中的那条**
（必须是 `clips` 里的一个，缺省 = 还没选，那时「播放」点不了）——它就是前端会播的那条，
所以它和 `layer` 一样是**场景数据**（重开项目还在、撤销能回退）。两者一起走：移出去的音频不留
名字，选中的那条被移走就顺到下一条。`names` 是 **「文件 → 显示名」** 的表（缺省就不写这个字段，
退回素材文件名）——按文件记，所以加进来的哪条都能起名，换选不会把名字弄丢。

前端要配合两件事：认 `kind: "PlaySound"` 与 `sound` 字段；按「**同层顶替** + `picked` 那条」播放。
（那枚图标只是**编辑器**的画法，前端按自己的表现来——它不参与协议。）

#### 怎么让它响：播放 / 停止按钮

「声音」组就四行：**层级**、**音频**（一排小方块，点一下换「播哪条」）、**编辑音频…**（开窗口）、
**播放**（`▶ 播放` / `■ 停止`）。开窗口的按钮**单独占一行**——挨着那排小方块放的时候，
想换声音很容易点到它（一个点错是换声音，另一个点错是弹窗口）。

#### 「编辑声音」窗口（加 / 删 + 改名）

属性面板太窄——**看不到路径就不知道源文件是哪个**，所以「加哪些音频」「叫什么名字」都在窗口里
（面板上那行「编辑音频…」唤出）。窗口里就是**这条声音对象的音频清单**，每行是
**名字输入框 + 项目内路径 + 「移出」**，右上角「**＋ 添加音频**」弹「**选择音频**」（列出项目里的
音频素材，点一条就加进来、可以连着加几条，已经加过的标「已加入」）：

- **加进来才播得出来**：面板上的小方块只在已加进来的音频里选，所以这是添素材的唯一入口；
- 窗口里**没有「选中」这种操作**——*播哪条*是属性面板上点小方块的事（见上），这里只管清单本身；
- 加进来时**不会顶掉**已经选的那条（正听着 A 的时候加一条 B，选择不该被换掉）；
- **名字就地改**（Enter / 失焦提交，Esc 还原；留空 = 用素材文件名）。名字按**文件**存
  （`sound.names`），所以哪条都能起名；
- 路径照原样显示（`audio/thunderstorm-30s-high.mp3`）；素材被删 / 手写文件里的条目也留一行，
  标着「找不到」，「移出」一下就清掉（**只从这条声音对象的清单里移出，素材文件不会被删**）。

| 按钮 | 做什么 |
|---|---|
| **▶ 播放** | 记下「这一层播这个对象的**这条**声音」，把它发给前端。记账一生效：**画布上那枚图标会动**（一圈圈声波往外扩），按钮也变成 **「播放中」+ 三根跳动的声音条**并高亮 |
| **■ 停止** | 记下「这一层停」，让前端停掉该层（画布图标与按钮状态都回到「没在播」） |

按钮右边那行小字就是**本层现在的状态**：`本层正在播：雷雨` / `本层正被「脚步」占着`
（同层同时只响一条，所以它自己没在播）/ `本层没在播`——**点下去有没有生效一眼就看得见**，
不用去翻运行日志。声音条是**纯 CSS 动画**（不引 JS 定时器、不让面板每帧重渲染；系统里开了
「减少动效」就不动，状态本来就有文字）。
（这份状态是运行态：不写文档、不进撤销栈，切场景 / 换项目后回到「没在播」。）

**随时点得动**——唯一的例外是「一条音频都没加」和「加了但没选」，那时只有「播放」置灰并写明原因。
原因是编辑器**只记账**：「哪一层现在该播什么」记在运行态里（`soundPlayback`，
**不写文档、不进撤销栈**，切场景 / 换项目清空；面板上不显示它，只在按钮的 tooltip 里说清楚
「现在能发下去」还是「已记录、等连上补发」）。

命令是**尽力发**，发不出去也不会丢：

| 点的时候 | 行为 |
|---|---|
| 前端连着（Unity / mock） | 立刻下发；前端回 `command_result` 后日志写「声音命令执行成功」 |
| 编辑器还没连服务端 / 前端没连 | 只记账，按钮 title 写明「已记录：…，连上后自动补发」；**前端连上的那一刻自动补发**一遍 |

协议上是**命令只当触发器**（`editor_command` → 服务端转 `command{kind:"play_sound", objectId, layer}` /
`{kind:"stop_sound", layer}`，前端回 `command_result`）：**命令里没有音频路径**——播哪一条由前端从
**自己镜像里的那个对象**读 `sound.picked`（数据在推下去的场景里）。前端没实现这条命令时，
编辑器会在 5 秒后把「命令回执超时：前端可能未实现 play_sound」写进运行日志（不静默失败）。

**手动验证**：起后端 → 编辑器点「运行」→ `pnpm --filter @dts/backend mock`（假前端会自动连上）→
选中声音对象 → 点 ▶：Mock 打印收到的命令并回执（它不出声，真出声在 Unity 里），
编辑器运行日志出现「命令执行失败：mock 前端不出声…」——**这是预期的**，它证明链路通了、回执回来了。
「**先点播放、再开前端**」同样成立：前端一连上，编辑器会把记着的每层补发一遍。

### 动作对象：传送阵

**「动作」种类下的第二个对象**——跑团时最常用的那个动作：**按一下，全场换到另一张图**
（DM 的「换台」）。它同样**和实体一样摆在世界里**（基础属性一个不少，能点选、能拖、能被挡住），
在此之上多一组「传送」。

**数据形状与「播放声音」完全同一套**：**候选清单** + **选中的那一个**（两个字段，分工别串）：

| 参数 | 说明 |
|---|---|
| **候选场景**（`teleport.targets`） | 这个传送阵**能去**的场景清单（可以勾多张）。存的是**场景名**——这个仓库里场景的标识就是文件名 |
| **传送到哪一个**（`teleport.picked`） | 候选里**现在选中的那一张**（按下去就传去这里）。只能从候选里选；还没选时按钮点不动 |

属性面板上就两行、几个可点的东西：**目标**（候选列成一排小方块，点一下 = 传送到它，再点一下取消；
末尾那枚 `＋` 开「**传送目标**」窗口勾清单）与**传送**（按一下换台）。
「传送」按钮**不写传到哪**——选中哪个小方块已经说明了，按钮只写动作；传不了时才在按钮上写为什么
（`先加目标` / `先选一个目标` / `目标已失效` / `已经在这个场景`），
免得平板上没有 hover、点不动却不知道为什么。

**触发它的两个入口**（同一件事）：属性面板的「**传送**」按钮；画布上**双击那枚徽标**
（鼠标的快路径；平板没有可靠的双击，所以按钮是主要入口）。触发 = **切换当前场景**：

- 走的就是切场景那条唯一的路（写回改动 → 记住视口 → 换场景 → **适配 / 恢复视口** →
  **立刻 `scene_push`**）——所以**运行中投影会跟着换**，不用再去运行面板点「重新同步」；
- **不改文档、不进撤销栈**：按一下换台不是编辑（与播放声音同一条规矩）。

**画布上的样子也是固定的**：一枚**内置的传送徽标**（实色圆角牌 + 深色外描边 + 白色旋涡与箭头，
与音频图标同一套画法、不占资产也不依赖字体），所以刚建出来的传送阵看得见、点得到、拖得动。
**图标不允许改**：属性面板里没有「渲染」这一组；手写文件里挂了 `image` 会被 `validateScene` 警告。
列表行尾显示的是它**现在会传送到哪张图**（没加 / 没选就写「未加目标」「未选目标」）。

落盘就是这两个字段（缺省不写空壳）：

```json
{ "kind": "Teleport", "position": { "x": 0, "y": 0 }, "scale": 1,
  "teleport": { "targets": ["Map002", "Map003"], "picked": "Map003" } }
```

`teleport` 整个缺失 = 数据坏了（`validateScene` 报错）；候选空 / 没选 / 选中的那个不在候选里
（手写文件）都是**合法状态**——按钮写明理由并点不动，只在校验里给警告，不写空串
（与 `sound.picked` 同一个口径）。候选里混着**已经不在项目里的场景**（改名 / 删掉之后）时，
小方块标红、「传送目标」窗口里也照常列出来并点明「已失效」（在那儿就能取消勾）。
更早那一版只写了单个 `teleport.target`：读文件时会自动搬成 `targets` + `picked`（见 `migrateTeleportTarget`）。

**它不需要新协议命令**：切场景本来就是编辑器的事——整份 `scene_push` 推下去，前端换镜像就完了。
前端也**不用为它建可见物**（与播放声音一样，动作对象一个 GameObject 都不建，数据留在镜像里即可）。
**场景改名不会自动跟随**：目标会变成「不存在的场景」，按钮写明理由并点不动，重选一次即可。

### 网格标注（地图编辑）

参考 Unity 的 `GridMapEditorWindow`：**把格子标成各种类型**（窗口里按顺序叫
「区域1–区域8」，位掩码仍与 Unity 的 `GridCellType` 对齐），
标出来的掩码就是前端运行时用的那份格子数据。

**改格子只有一个地方**：属性面板的「**区域** → 网格标注 → **编辑**」按钮打开的
**网格编辑窗口**——贴图铺满窗口，落笔就落在格子上，不用在地图上对准格子，
也不用先切进什么模式。窗口布局与战争雾窗口一致：**画布在左**，
**标记类型**（橡皮擦 + 8 个区域 + 每类的显示开关 + 画笔大小）在右；
**尺寸按主窗口比例算**（宽 80%、高 86%，夹在 `720×520 ~ 1680×1200`，且绝不超过窗口的 92%），
窗口一缩放就跟着变——写死的 820×560 在宽屏上白瞎画布。

窗口自带视口（`fitViewport` 把这张地图装满），所以**不要求地图已激活 / 已落位**。
注意它和「战争雾」的 Mask 窗口是**两回事**：这边是**格子级**的编辑（改的是 `map.cells`，
进撤销栈、会落盘），那边是**运行时的遮罩擦除预览**（像素级、只有擦除、不写文档）。

窗口右侧面板（与 Unity 右侧面板一一对应）：

| 控件 | 说明 |
|---|---|
| 画笔大小 | 1–5 的滑杆；半径 `floor((n-1)/2)`，所以 1/2→1 格、3/4→3 格、5→5 格（**与 Unity 完全一致**） |
| 标记类型 | 「橡皮擦 (0)」+ 8 种类型（`区域1`…`区域8`）；**点名字即选画笔**。名字是**中性占位**：编号 1–8 是**顺序**，位值另算（1/2/4/8…） |
| 显示开关 | 每类右边的勾选框：**只影响绘制**（窗口与画布一起），数据不动；关掉的那类**照样画得上去** |
| 颜色 | 每类左边的取色器：**只能改 RGB**，透明度跟类型绑定（对齐 Unity 把 alpha 关掉的那套默认色） |
| 全部清除 | 把整张网格恢复成空（可撤销）；已经空着时禁用 |

属性面板的**「显示」**那行还有**两个总开关**（在「网格标注」上面，**不开窗口也能用**）：

| 开关 | 关掉以后 |
|---|---|
| **网格线** | 画布上不再画网格线，只剩贴图（想看清美术时随手关） |
| **网格标注** | 格子不再着色（想只看底图时关）；**画笔照样能画**，只是看不见颜色 |

两个都是**纯显示开关**：数据、撤销栈、画笔、落盘一概不受影响；和「每类的显示开关」一样
记在浏览器本地，作用于画布上的**所有地图**（一个场景可以有多张）。

**规则与 Unity 一致**（`packages/grid` 里有对照实现与单测）：

- 类型是**位掩码**，同一格可以叠多个（窗口里显示成 `区域1` + `区域4`，位值即 `Obstacle | Fog1`）；
  画笔是**按位或**，不清除已有的位；
- **橡皮擦 = 掩码 0 = 整格清零**；
- **落笔点必须在网格内**，在地图外面点一下什么都不做（不夹到边缘格，也不取消选中）；
- 一格里多个类型**逐位半透明叠加绘制**，高位先画、低位在上（和 Unity 的绘制循环同序）；
- 一整笔（按下 → 抬手的若干次 pointermove）会**补齐两个事件点之间的格子**，快拖也不断线；
  一整笔只留**一条撤销记录**（下一次落笔才是新的一条）。

**数据落在场景文件里**（`Assets/scenes/<场景名>.json` 的 `map.cells.runs`，RLE），
不写 `.bytes`：编辑器这边场景文件就是地图数据的家，导出 `.bytes` 属于后续里程碑
（编解码已经在 `@dts/grid` 的 `bytes.ts` 里备好）。改动照样走**自动存 + 撤销栈**：
涂完 800ms 自动写盘，底栏显示保存状态，`Ctrl/⌘+Z` / `Ctrl/⌘+Shift+Z` 可撤销重做。

**画笔偏好记在浏览器本地**（`localStorage` 的 `dts.editor.gridPaint`：画笔类型 / 大小 / 每类的显示与颜色 /
网格线、网格标注两个总开关，以及战争雾那个开关）——对齐 Unity 把这些存在编辑窗口的序列化字段里：
换个项目、重开浏览器，显示方式、手感与配色都还在。

### 战争雾（地图）

**整组由「战争雾」那一行的开关管着**：关着时只显示这个开关，打开以后才露出雾区设置——
没开战争雾的地图不该摆着一排用不上的按钮。它是**编辑器偏好**
（与网格线 / 网格标注同一份本地偏好，不进文档）。

**画布上不画雾**：雾用的就是区域数据（`map.cells` 的 8 个区域位），画布上只有「区域」那一套
着色，看雾去它自己的 Mask 窗口——画布上再盖一层只会把同一批格子画第二遍（区域层 + 雾层
叠成两块深浅不一的网格），而雾并没有第二份数据可画。

打开之后，**雾区还得手动指定**：格子上的 8 个类型位是中性的「区域」，不代表具体玩法，
所以「哪些区域算战争雾」是**这张地图自己的配置**——「指定雾区」里点几个区域按钮即可，
写进场景文件的 `object.map.fog.regions`（如 `[8]` = 区域4）。没指定任何雾区时**不写这个字段**，
Mask 窗口也打不开（先指定才有意义）。指定之后，「雾格子」那行的「**编辑**」打开 Mask 窗口。

**Mask 窗口**（模态对话框）是**运行时的那个工具**在编辑器里的样子：贴图铺底、上面盖一层
未探索的雾（见下：编辑器里按**区域颜色**、能一眼看出哪块是哪区），**只有擦除**——按住涂抹就等于 GM
在跑团现场揭示地形；**运行态下这一笔会下发给前端**（只发轨迹）。移植自参考实现
（`backend_diceTale` 的 `MaskEditorDialog.vue` + `composables/useMaskEditor.ts` + `services/maskMath.ts`，
公式与 Unity `MaskImage` 的 shader 同一套，见 `apps/editor/src/services/mask-math.ts`）：

- **不是擦格子**：遮罩是一张**纹理**——**960 宽**（参考实现 `MaskImage.maskWidth` 的默认尺寸，
  运行时那张也是这个尺寸）、高度按贴图比例推（圆刷显示不变形；极端长宽比等比缩到长边 2048）；
- **擦除算法与前端逐字对齐**（`MaskImage.ApplyEraseStroke` + `MaskEraseStamp.shader`，见 `mask-math.ts`）：
  半径 = **归一化半径**（`48/960 = 0.05`，真正跨端传的那个数）× 遮罩宽；
  沿线段按 `step = max(1, 半径 / 2)` 补点（两端各打一个圆，快拖不断线）；
  每个落点按「**纹素中心**到圆心」的距离算 `core = 半径 × (1 - 软边)`、
  `alpha = min(原值, saturate((d - core) / max(半径 - core, 1e-5)))`——核内全擦、核外线性收尾、
  `min` 幂等（同一处擦多次 = 一次）。所以**同一个归一化半径在两边擦出的是同一片纹素**；
  编辑器这边只是颜色与落盘不同（前端雾是统一的雾色、擦除不写文档；这里按区域配色画，好看清哪块是哪区）；
- **右侧是「整区开关」**：每个已指定雾区一个勾选框——**打开 = 这一区整片揭示**、
  **关闭 = 整片盖回去**（与运行时 `FogOfWar` 的「玩家进区 → 清除整片区域」同一个意思）。
  它和手动擦一样只在本窗口里生效、不写文档、关掉重开复位；开一个区不影响别的区。
  ⚠️ 一格同时属于两个雾区（`区域1 + 区域4`）时会被**整块**揭示——像素遮罩一格只有一块纹素，
  分不出「只擦掉其中一位的那一半」；运行时那边是按「雾位组合」分组的（`Fog1|Fog2` 自成一组），
  所以这一处比运行时略粗。- **按区域颜色显示**：罩子画的是**已指定雾区**的格子，每个区域用它自己的配色
  （与「网格标注」同一份偏好；一格同时属于两个雾区时逐层叠加）。运行时（Unity）那边雾是
  统一的黑色/雾色，但那是前端重构之后的事——编辑器里按区域颜色才看得出哪块是哪区；
- **不碰文档**：擦了不写 `map.cells`、不进撤销栈、不落盘，只是这一窗口里的预览；
- 初始状态 = 运行时那份：**已指定雾区的格子**盖着颜色，其余透明；
- 每次打开都按当前文档重画，所以**关掉再打开就回到未探索的样子**；指定雾区的绑定改了，
  重开也按新的画；
- 没有画笔 / 画回去 / 全部清除（雾只会被揭示，不会被重新盖上）。

**与运行时的对应**（`DiceTale/client/Assets/DiceTale/Scripts/Presentation/FogOfWar.cs`，**已实现**）：
运行时（Unity）按 `map.fog.regions` 从 `map.cells` 里挑出**雾格子**，生成一张像素遮罩盖在地图上
（**与这里的 Mask 窗口同一张尺寸**：960 宽、高按贴图比例推），由后台发来的**鼠标轨迹**沿轨迹擦。
编辑器里雾**按区域配色画**（Mask 窗口里那个罩子：与「网格标注」共用配色），而**画布上不画**——
画布只画区域着色，雾的呈现只在 Mask 窗口里，在它上面**擦除**就是预览「揭示之后是什么样」。
运行时那边雾是统一的雾色（`fogColor`，默认黑不透明），颜色不同、**形状与擦除范围一致**；
雾的**边缘会羽化**（`FogBlur` 模糊链，约一格宽）——所以投影上看到的是软边的雾，
而编辑器预览里仍是硬边格子（那是给 DM 看清「哪几格算雾」用的）。

**绑定的是任意可绘制的区域位**：`map.fog.regions` 里写哪几位、运行时就按哪几位挑雾格
（`[1, 2, 4]` = 区域1/2/3 也算雾区）——不再限定 `Fog1–Fog5`，与编辑器完全同一套口径
（`.bytes` 导出仍是后续里程碑，绑定位不进 `.bytes`）。

**擦除已经下发给前端**：运行态下在 Mask 窗口里擦一笔 / 拨一个「整区开关」，编辑器就尽力下发
`erase_mask`（**只发轨迹**，不发整张遮罩）/ `reveal_fog_region`；前端没连时先记账，等它（重）连上补发。
拖动中是分批发的（攒够几个点或过一会儿一批），成功回执不写日志（失败照写），所以运行日志不会被刷屏。
前端那边**揭示状态留在自己的雾层里**（不写文档）：切场景、重连（视图不销毁）都保留，
Unity 重启才回到未探索。

⚠️ **这一版动了协议版本（v2 → v3）**：新增的两种命令，**老服务端的入站校验不认识**——它会回一行
「消息校验失败」并把命令丢掉（现场踩过一次：服务端进程没重启，表现是「点了有报错、投影一动不动」）。
所以升级后**服务端要重启**（`command-start.bat` 那个窗口关掉重开）、**Unity 客户端要重新编译**；
版本握手会在连上的那一刻就把「新旧不一致」写成一句人话，不必等第一条命令发出去才发现。

## 打开编辑器时

编辑器启动会跑一次**启动引导**（`bootstrapEditor`），规则只有三条：

| 情况 | 行为 |
|---|---|
| 有「上次打开的项目」且它还在 | **直接打开它**，不弹对话框 |
| 一个项目都没有 | 弹「**新建项目**」 |
| 有项目，但没有（或已失效的）上次记录 | 弹「**打开项目**」列表让用户挑 |

- 「上次打开的项目」记在**浏览器本地**（`localStorage`，见 `apps/editor/src/services/session.ts`）：
  打开动作由浏览器发起，服务端只知道文件夹在不在，不知道谁上次开了哪个项目。
- 主动「关闭项目」= **忘记**它，下次启动不会又把它拉回来。
- 记录失效（项目被删 / 改名 / 项目文件坏了）时自动清掉记录，退回「打开项目」列表，不会卡住。
- 引导是否跑完、弹了哪种对话框，通过外壳上的 `data-bootstrapped` 与 `data-project-dialog`
  暴露出来（e2e 据此等待引导结束，避免启动对话框把点击吃掉）。

## 资源：一个项目 = 一个文件夹 + 一个 project.json + 一个 Assets/

**每个项目是唯一的文件夹**，项目根只有两样东西：一个**固定名**的项目文件，和一个 `Assets/`
（模板参考 Unity：除项目文件外的一切都在 `Assets/` 下，项目根不随功能增长变乱）：

```
resources/
├─ config/                            编辑器全局配置（不属于任何项目）
│  ├─ app.json                        端口、资源目录名、项目标准子目录
│  ├─ editor.json                     编辑器默认值
│  └─ export.json                     导出目标
└─ projects/                          ★ 所有项目
   └─ 我的项目/                        ★ 一个项目一个唯一文件夹
      ├─ project.json                 ★ 项目文件（固定名；只有项目级数据）
      └─ Assets/                      ★ 所有资源都在这里
         ├─ config/                   该项目自己的配置
         ├─ scenes/                   ★ 场景：<场景名>.json（场景名就是文件名）
         ├─ images/                   图片资源：场景贴图 <场景>.png（与场景同名）
         ├─ audio/
         └─ video/
```

编辑器里：「工程 → 新建项目」起个名字即创建出上述结构；「工程 → 打开项目」列出所有项目。
场景（含网格与对象）是 `Assets/scenes/<场景名>.json` 独立文件；`Assets/` 下还放导出物与素材。

**资源不由编辑器写入**：素材由人 / 外部工具**提交到这些指定目录**，编辑器只负责查看与引用，
所以资源面板目前是**只读**的（没有新建 / 导入 / 删除入口）。例外只有两类，都不碰素材本身：
场景的三个文件级操作（新建 / 重命名 / 删除），以及**场景对象的编辑**（写的是 `Assets/scenes/`
下的场景文件，不是 `Assets/` 里的素材）。

**资源面板标题栏的「打开目录」**用文件管理器打开**当前项目目录**（项目根，里面就是
`project.json` + `Assets/`），方便往里丢素材。三件要说清的事：

- 弹出来的是**运行服务端那台机器**上的窗口——浏览器出于安全不允许替用户开文件夹，
  所以由后端调系统命令做（Windows `explorer.exe` / macOS `open` / Linux `xdg-open`）；
  从平板经局域网访问时，开的是那台电脑的目录，不是平板上的文件 App；
- 路径**由服务端按自己的配置拼**（`资源根 / <projects> / 项目名`），项目名先过 `validateProjectName`，
  客户端**不能**指定任意路径（`POST /api/projects/reveal`，只收 `{name}`）；
- 打不开（系统不支持、命令缺失）时如实报在资源面板的红字里，不会「点了没反应」。

**选中资源看属性**：在资源面板里点一个文件即选中它，属性面板显示名称 / 路径 / 类型 / 大小，
图片还会读出**真实像素尺寸**；图片、视频、音频直接在属性面板里预览。预览走后端的原始字节接口
（`/api/resources/raw?id=...`），所以刚提交进目录的素材刷新一下就能看到，不需要先「导入」。
列表里**不显示扩展名**（`Map001.png` 显示为 `Map001`），完整文件名在属性面板里看。
例外：`Assets/scenes/` 下的场景文件点一下是**打开那个场景**（不是看属性），
当前场景那一行会在目录里高亮——对齐 Unity「Project 窗口里双击场景即打开」的习惯。

**属性面板不跟场景绑定**：选中资源看资源属性、选中对象看对象属性，都没选时看**项目属性**
（名称 / 文件夹 / 场景数 / 资源文件数）——打开着项目就总有内容，不会因为「没有场景」而空白。

**属性按组分块，每组可折叠**（对齐 Unity 的组件头 / 参考实现的 `PropertySections`）：
点分组标题那一行收起或展开，**默认全展开**，**切换对象时回到展开**
（免得「上一个对象收起的分组」跟着跑到下一个对象身上）。网格地图分四组：

| 分组 | 内容 |
|---|---|
| **基础** | 名称 / 类型 / 激活 / 锁定 / 显示顺序 / 世界坐标 / 缩放（等比锁 + 可选的 X / Y 单轴）/ **角度** |
| **渲染** | **这个对象画出来是什么样**：现在只有**贴图**（换一张图片）。暂时只做到替换图片，后面加的渲染选项（着色、混合、动画…）都归这一组 |
| **区域** | 地图的网格规格（列 · 行 / 每格 / 行序）、网格线 · 网格标注两个显示开关，以及「**编辑**」（网格编辑窗口：涂 / 擦格子、画笔与配色，不用在地图上对准格子） |
| **战争雾** | 一个「战争雾」开关管整组（关着时只留它）：打开后才有 指定雾区（8 个区域按钮，手动绑定哪几个区域算战争雾）+「**编辑**」（雾格子 → 战争雾 Mask 窗口：擦除 / 整区开合） |

看相上三件事是定死的（`panels/inspector/fields.tsx`）：**表头是一条始终有底色的「条」**
（主题里的 `--color-editor-bar` + hover 变亮，点整条收起 / 展开）、
**箭头是 16px 的内联 SVG**（展开时旋转 90° 朝下，不用只有 ~10px 的 `▾` / `▸` 字形）、
**组内不放行分隔线**——靠表头条与卡片外框分组就够了，每行再画一条线会把属性面板变成一张表格。

其它类型的对象有「基础 / 渲染」两组（每个对象都能显示一张图片，只是地图还有格子可编辑）；
场景 / 资源 / 项目属性各一组，同样是可折叠的。
**折叠只影响「看见什么」**：数据、撤销栈、画笔一概不受影响。

**判定标准只有一条：文件夹里有 `project.json` 才是项目。** 没有的目录（半途创建、只剩资源的残骸）
不会出现在「打开项目」列表里，也不算存在——`listProjects` 直接过滤掉它们。

`Assets/` 下的标准目录是 `config`、`scenes`、`images`、`audio`、`video` 五个。
**没有 `maps/`**（地图只是场景里的一个对象，数据按场景放 `Assets/scenes/`），
**也没有 `items/`**（道具库存在项目文件里）。

仓库里带一个 `测试项目/` 作为样例（也是手测用的空项目）；E2E 不会碰它——
Playwright 跑在临时资源根上（见 `playwright.config.ts` 的 `DTS_RESOURCES_DIR`）。

- 资源用**逻辑 ID** 寻址，只有两个类别：`config:`（编辑器全局）与 `project:`（项目内容）。
  例如 `project:我的项目/project.json`、`project:我的项目/Assets/images/Map001.png`。
- **特殊文件不出现在资源面板里**：`project.json` 是项目元数据、不是项目内容，
  资源树会跳过它（`PROJECT_SPECIAL_FILES`）——因此它既不显示，也无法从面板里被删掉
  （删掉它项目就不成立了）。只挡项目根的那一个，子目录里同名的文件照常显示。
- 项目文件夹名、标准子目录名与项目文件名集中在 `packages/resources/src/ids.ts`
  （`PROJECT_FOLDERS`、`PROJECT_FILE_NAME`）；资源根与 `projects` 目录名由 `config/app.json` 的 `dirs` 声明。
- 逻辑 ID → 真实路径的解析只发生在 `ResourceProvider` 实现里（后端 `FsResourceProvider`、编辑器 `HTTP`、测试 `Memory`）。
- 项目名会直接成为文件夹名，因此会挡掉路径分隔符、Windows 非法字符与 `CON`/`NUL` 等保留名。
- 大体积二进制（地图贴图、音视频）默认不入库，需要时 `git add -f` 或启用 Git LFS。

### 运行态资源包（前端连上就把整个项目的素材拉到本地）

前端**不再逐张图去问服务端**：连上、拿到场景（从而知道当前是哪个项目）之后，它会把该项目的
`Assets/` **整包拉一份到本地**，之后所有资源从本地文件读，服务端只在素材变了时才需要再传一次。

| 接口 | 说明 |
|---|---|
| `GET /api/resources/manifest?project=<项目名>` | 清单：项目名 + **指纹** + 字节数 + 文件列表（`id` / `path` / `size` / `mtimeMs`）。只列 `Assets/` 下的文件——`project.json` 是元数据、`.gitkeep` 是占位，都不下发 |
| `GET /api/resources/bundle?project=<项目名>[&v=<指纹>]` | 整包 zip。`v` 与服务端当前指纹一致 → **304**（客户端不必重下）；否则 200 + `application/zip`，响应头带 `x-dts-project` / `x-dts-fingerprint` / `x-dts-file-count` / `x-dts-bytes` |

**指纹 = 全部文件 `path:size:mtimeMs` 排序后拼接的 sha1 前 16 位**（`apps/backend/src/resources/bundle.ts`）。
素材被外部工具改动（大小或修改时间变了）指纹就变，客户端下次连上即发现并重下；
指纹没变则一个字节都不传。

包的做法与取舍（`bundle.ts` 顶部注释也写了同一份）：

- 包内条目名 = **项目根相对路径**（`Assets/images/Map001.png`，不带项目名前缀），
  前端按逻辑 ID 去掉项目名后直接对得上本地文件；另含一份 `dts-bundle.json` 清单便于自校验。
- **压缩方式刻意选 STORED（不压缩）**：后端没有 zip 依赖，自研 writer 用 STORED 才不必实现 deflate；
  素材本身（png / mp4 / mp3 / wav）已经是压缩格式。代价是传输量 = 文件字节总和。
  **产出的包用 .NET 的 `ZipArchive` / `Expand-Archive` 实地解压验证过**（中文条目名也正确）。
- **整包在内存里拼**：`config/app.json` 的 `bundle.maxTotalBytes`（默认 256 MB）是上限，
  超了回 **413** 并让前端退回逐文件 `/api/resources/raw`——不设上限会在大项目上把内存吃光。
- 服务端**每个项目只缓存最近一份**打包结果，但进缓存前会**重算指纹**（成本 = 一次 `list`），
  所以素材改了会自动重打，不需要文件监听，也不会发出发霉的包。

前端侧（`client/`）：`ResourceBundleCache` 负责「问清单 → 按需下包 → 后台线程解压 → 写指纹标记」，
`LocalResourceStore` 负责路径约定（逻辑 ID ↔ 本地文件、版本目录的选择与清理），
`ResourceImageLoader` 本地优先、缺的回落远程。拉完（或失败）前端会回一条 `resources_ready`，
编辑器运行面板上能看见「资源包：已就绪 / 失败 + 项目 + 文件数 + 指纹」。

**顺序：先下资源、再载入场景。** 服务端在 `scene_sync` **之前**先发一条
`resources_prepare{project}`（项目名从最近一次推上来的场景里的资源逻辑 ID 推出，
见 `runtime-session.ts` 的 `projectNameOfScene`），前端据此立刻开下；场景到了会被前端挂起，
等资源包处理完（成功或失败都算）才落地。因此协议版本升到 **v2**——`/client` 多了一种消息类型。

## 编辑态 / 运行态

- **编辑态**：编辑场景对象（新建 / 改名 / 删除 / 复制 / 拖动定位）、**动作对象**（播放声音：
  音频列表 + 层级；传送阵：候选场景 + 选中的那一张——按一下就是「换台」）与**地图网格标注**（画 / 擦格子类型），
  全程可撤销/重做（补丁式历史，连续拖拽 / 一整笔涂抹 / 复制会合并成一条记录）；
  组件编辑与「把动作挂到组件上」的编排尚未落地（动作种类目前有两个对象：播放声音、传送阵）。
- **运行态**：点「运行」后编辑器声明运行态（服务端**开闸**），把**当前场景整份推下去**；
  之后每次编辑（去抖 200ms）再推一份全量，前端按对象 `id` 增 / 改 / 删自己的对象。
  **运行中照样能改**（隐藏对象、拖位置、涂格子…这些改动立刻推给前端看效果），但**一律不写盘**：
  对齐 Unity 的播放模式，进入运行时先给整份文档拍一张快照，退出运行时**整体还原**——
  运行期间试出来的样子既不留进文件，也不留进撤销栈（场景的新建 / 改名 / 删除这类落在**文件**上的
  操作则直接挡住，提示先点「编辑」退出运行）。底栏与运行面板都会写明「运行中（不保存）」。

## 数据方向：后台有什么对象，前端就有什么对象

**后台（编辑器文档）是唯一真源，前端只是它的镜像 + 播放器。**

| 环节 | 做什么 |
|---|---|
| 编辑器点「运行」 | 连服务端 → `runtime_start`（**服务端据此开闸**）→ `scene_push` 推当前场景 |
| 编辑场景 | 文档一变就（去抖 200ms + 内容去重）再推一份全量 |
| 服务端 | 缓存最近一份场景；转发 `scene_sync` 给前端；把运行态摘要广播给编辑器 |
| 前端 | 按 `id` 建 / 改 / 删 GameObject：位置、缩放（等比看 `scale`；**单轴 `scaleX` / `scaleY` 是可选的，老前端忽略它们即可**）、旋转、**激活**、显示顺序、贴图。**动作对象（`PlaySound` / `Teleport`）只留数据、不建 GameObject** |
| 命令（如播放声音） | 只是**触发器**：`play_sound{objectId, layer}` 里没有音频路径，前端从**自己的镜像**读 `sound.picked` |
| 传送阵 / 切场景 | **没有命令**：编辑器换场景 → 整份 `scene_push`（立刻推）→ 前端按新场景名换整份镜像 |

**没点「运行」时前端根本连不上**：`/client` 的 WebSocket 升级会被以 **HTTP 503** 拒绝（`x-dts-reason: runtime-inactive`），
而不是「连上再被踢」。**运行态记在服务端**：编辑器刷新页面 / 关掉页面 / 断线都**不影响**它——
前端照旧连着、镜像还在；只有点「编辑」（`runtime_stop`）或服务端重启才关闸（关闸踢前端，close `4003`）。
编辑器页面加载时就连服务端要一份状态，所以刷新后如果服务端还在运行，界面会自动回到运行态。

协议定义以 `packages/protocol` 为唯一来源（编辑器与后端共用，入站消息全部经过 zod 校验），
字段口径与门控细节见 [`docs/specs/2026-09-19-runtime-mirror-protocol.md`](docs/specs/2026-09-19-runtime-mirror-protocol.md)。

## 前端（Unity 客户端）要做的

前端只做「镜像 + 播放」，要做的事已经落地在 `client/Assets/DiceTale/Scripts`：

1. **认协议**（`Network/`）：`client_hello` 自报家门；收 `server_hello` / `scene_sync` / `command` / `ping`；
   回 `command_result` / `pong`。协议版本不一致时服务端以 close `4002` 断开。
2. **建镜像**（`Logic/SceneMirror.cs` + `Presentation/SceneObjectView.cs`）：一份场景 = 一批对象；
   同 `id` 复用、缺的销毁；位置 / 缩放 / 旋转 / 激活 / 显示顺序逐项同步。
   **坐标换算**：文档世界坐标 `(x, y)`（y 向上）→ 客户端 `(x, 0, y)`（地面是 XZ 平面，与 `GridMap.WorldToGrid` 同口径）。
3. **取资源**（`Presentation/ResourceImageLoader.cs`）：对象里的图是**资源逻辑 ID**，
   走 `GET /api/resources/raw?id=…` 取字节；没图时先用按 `kind` 上色的占位矩形。
4. **收命令**（`Logic/CommandRouter.cs`）：`play_sound` / `stop_sound` 从镜像里读数据再执行，
   `erase_mask` / `reveal_fog_region` 找到那张地图的雾层（`Presentation/FogOfWar.cs`）再揭示，
   **无论成败都回 `command_result`**（不回的话编辑器 5 秒后会报「命令回执超时」）。
   当前 `play_sound` 的真出声（取音频 + 按层播放）是下一步，前端如实回 `ok:false` 并说明原因；
   战争雾那两条**已经实现**。

## 坐标契约（务必遵守）

**只有一套坐标系——世界坐标**：x 向右、**y 向上**，单位像素，而且**世界无限大**——
没有「场景范围」、没有边界，坐标可以是任意有限数（负数、几万都合法）：

```
                    (0, +∞)
                      │
       (-∞, 0) ───── (0, 0) ───── (+∞, 0)      世界原点只是一个参考点
                      │                       （地图、对象都可以摆在别处）
                    (0, -∞)
```

- **地图是世界里的对象**：它有 `position`（= **贴图中心**的世界坐标）与自己的贴图尺寸，
  占世界里的哪块矩形、它的格子从哪儿数，全由它自己决定。一张场景里可以有任意多张地图，
  各画各的（贴图、格子、网格线都裁剪在各自那块矩形里），互不干扰。
- **场景文件里的 `position` 就是世界坐标**（可以是负数）；协议里的位置（前端上报对象 / 玩家、
  擦除笔画、传送落点）也是同一套，前端照同一套实现即可。**前端要把地图的 `position` 也算进去**：
  格子 ↔ 世界坐标的换算依赖它（`grid (0,0)` 在那张地图矩形的左下角，不是世界原点）。
- **网格不是第二套坐标系**，只是按格子量化：`grid (0, 0)` 在**那张地图矩形的左下角**，
  `grid.y` 与世界 y 同向。
  `.bytes` 行序固定 `bottom-up`（文档里显式声明 `rowOrder`），第 0 行就是世界 y 最小的那一行。
- **网格只存列数与行数**（属性面板里可改）：每格的像素尺寸是算出来的
  （`贴图宽 ÷ 列数`、`贴图高 ÷ 行数`，1920×1080 分 64×36 就是每格 30×30），
  改尺寸会把格子按新规格重建（重叠部分原地保留，多出来的格子是空、被缩掉的丢弃）。
- **唯一的翻转**发生在贴图绘制那一步（图片的 y 天生向下），锚点由 `worldRectTopLeft()` 给出。
- 换算全部走 `packages/grid/src/world.ts`（世界 ↔ 网格，都收一个 `WorldRect`），**不要在别处再写一遍**；
  「世界 ↔ 屏幕」是相机的事，走 `packages/renderer/src/viewport.ts`。
- **视口默认装下整个场景**：打开场景 / 转屏 / 拉开面板时调 `fitSceneViewport()`——把当前场景里
  **画布上看得见的东西**（地图 / 精灵 / 徽标…）的并集外框居中装进视口。
  「复位」按钮与「视图 → 适配视口」是**同一件事**（都是它），因为对 DM 而言「复位」要的就是
  「让我重新看见全场」；**只缩不放（上限 1:1）**：装得下就按 1:1 摆中间，装不下才缩。
  一个对象都没落位时退回**世界原点居中、1:1**（`createCenteredViewport`）。
  世界无限大，所以平移**不夹取**（`clampViewport` 已删除）。
- `Map001` 实测：1920×1080 图 / 64×36 格 / 每格 30px。

### 旧文件的迁移（v9）

`formatVersion` **4 及更早**的场景文件里，位置是**归一化坐标 `[0,1]`（y 向下）**。
打开项目时按贴图尺寸换算成世界坐标并回写一次（**地图的位置照常换算**，它也是对象）：

```
world.x = norm.x * width  - width  / 2
world.y = height / 2 - norm.y * height
```

换算需要贴图尺寸：优先取场景里地图对象的贴图尺寸，取不到用兜底尺寸 1920×1080。
**越界的旧值原样保留**（不静默夹到边界——那会把错误数据伪装成正确数据）。

每一步迁移只认**它自己那条版本线**（位置是 v5，网格字段是 v6）：条件写成「< 当前版本」
的话，版本号一涨就会把已经是世界坐标的 v5 文件再换算一次（`(0,0)` 变成 `(-960, …)`）。

v6 起网格里不再存 `cellSize`（那个恒为 1 的字段谁也没读过，每格尺寸是 `贴图宽 ÷ 列数`
算出来的），旧文件打开时丢掉它并回写一次。没有位置（`position: null`）的地图会**补成世界原点**
——地图必须有位置才能渲染，而世界原点正好是它以前被隐式绘制的那个位置（画面不变）。

v7 给每个对象加上 `active`（是否显示）与 `sortingOrder`（显示顺序）。旧文件里没有这两个字段，
语义只能是「显示、顺序 `0`」，所以**schema 给默认值**（写成必填会让所有旧文件直接读不开），
读出来后在内存里补全并**回写一次**，保证「内存里的样子」和磁盘上的一致。

v8 给每个对象加上 `scale`（统一缩放，**默认 1 = 原始尺寸**）。v7 及更早的文件里没有它，
语义只能是 1，同样由 schema 给默认值 + 读出来补全后回写一次。缩放只放大对象那块矩形
（贴图与地图的网格一起缩放），位置始终是缩放后矩形的中心；`0` / 负数这类坏数据不在 schema 层硬拒
（读不开比画不出来更糟），由 `validateScene` 报错、渲染端按 1 兜底。

v9 给每个对象加上 `locked`（是否锁定，**默认 false = 不锁**），同样由 schema 给默认值 + 读出来补全后
回写一次。锁只拦「移动」这一件事：画布拖动与属性面板改坐标**都走 store 的 `moveObject`**，
护栏就放在那一个入口上，两条路一起被拦住；画布在按下时还额外判一次（锁住的对象不进拖动状态，
按住它拖 = 平移画布）。

v10 给**地图对象**加上 `map.fog`（战争雾：指定哪些区域算雾区）。它**没有默认值可补**——
「没指定」在文件里就是**没有这个字段**（与 `{ regions: [] }` 同义），所以读出旧文件时不额外写一个
空壳进去，只是把版本号升到 10 并回写一次。旧文件（没有 `fog`）= 一个雾区都没指定，
画布与行为与之前完全一致（战争雾那个开关默认关着，整组设置都收着）。

v11 给每个对象加上**可选的单轴缩放** `scaleX` / `scaleY`。语义与取值规则：

- 它们**存在时覆盖** `scale` 在对应那一轴上的值；**没写 = 用等比的 `scale`**。
  所以旧文件（只有 `scale`）读进来仍然是对的，全客户端也照旧只看到等比——
  这正是「不换掉 `scale`」的理由：它是 v8 起就在文件、协议与 Unity 客户端里的字段；
- **读**一律走 `effectiveScaleX` / `effectiveScaleY`（`packages/document/src/scale.ts`），
  不要直接读字段，否则会漏掉「缺省 = 用等比值」这条；
- **写盘前**一律走 `collapseScale`：两轴相等就**折叠**回单个 `scale`（把两个轴字段整个摘掉）。
  少了这一步会出两个问题——等比对象也会写出两轴字段（还没更新的 Unity 客户端不认），
  而且反复拖手柄的浮点误差会把「其实等比」的对象永远钉在非等比形态上；
- 坏值（`0` / 负数 / `NaN`）在**写**路径上「夹而不拒」（`0` → `0.01`，与输入框既有行为一致），
  在**读**路径上退回原始尺寸 `1`：把坏数据夹成 `0.01` 会把「文件写坏了」伪装成「对象特别小」，
  画布上正确的做法是按原始尺寸画出来，让 `validateScene` 去报那个坏数字；
- **Unity 客户端本次没动**：它按等比渲染，两轴字段被忽略。要让客户端也看到非等比，
  是独立的一次改动（读这两个字段后传给 `TextureRenderer.Apply(w, h)` ——
  渲染器本来就吃两个尺寸参数）。

**更高版本的文件直接拒绝打开**（读不懂的字段被静默丢掉再回存，等于把数据毁掉）。

## 已知限制与下一步

- 编辑器已完成：四区布局、画布视口、场景对象与**地图网格标注 / 战争雾**、运行态面板；
  组件 / 动作编辑、导出（含 `.bytes`）按里程碑推进。
- 标注的橡皮仍是**整格清零**（与 Unity 一致）。`@dts/grid` 的 `applyBrush` 与
  `@dts/document` 的 `paintMapCells` 都支持 `eraseMask`（只清指定位，有单测），
  但目前**没有 UI 在用它**：战争雾的 Mask 窗口是像素级擦除（擦的是遮罩那张图，不是格子）。
- 网格标注仍不支持区域填充 / 矩形工具、格子复制粘贴；也不支持命名的格点标记。
- 战争雾的绑定位（`map.fog.regions`）**不进 `.bytes`**；运行时（Unity）已按它挑雾格，**不再限定
  `Fog1–Fog5`**——任意可绘制的区域位都算数（见「战争雾」一节）。
- 地图对象的 `rotation ≠ 0` 目前不参与渲染与网格换算（网格按轴对齐画与标注）。
- 变换手柄**只作用于单选**：多选时每个对象照画选中框，但不出手柄（Unity 会把整体缩放）。
  也不做网格吸附（Unity 的 `Ctrl` 吸附）。
- 单轴缩放（`scaleX` / `scaleY`）已进文档与协议，但 **Unity 客户端仍按等比渲染**（见 v11 迁移一节）。
- Playwright 目前用 Chromium 覆盖桌面与平板（触摸模拟）；真实 iPad/Safari（WebKit）档位需额外下载 WebKit 浏览器后补充。
- 服务端权威动作求值（多步序列、服务端条件判定）尚未实现。
